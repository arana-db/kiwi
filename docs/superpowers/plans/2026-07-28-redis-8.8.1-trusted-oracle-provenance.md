> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法跟踪进度。

**目标：** 在新的独立实现 task 中建立 Redis 8.8.1 primary build、verifier fresh-checkout independent rebuild、binary SHA-256 equality 和 cleanup-before-publish 的正式 Oracle provenance。

**架构：** Primary builder 产生候选 binary 和审计 metadata，但不为自己授信。Verifier 从 held exact source 创建全新 disposable checkout，使用 verifier-owned 受控 Python/Git/CC/Make 独立构建，要求两个 binary hash 完全一致，只运行 verifier rebuild binary 取得 `INFO server`，并在所有进程和临时目录清理成功后发布 provenance v2。

**技术栈：** Rust 1.97.1 test-only `kiwi-compat` crate、Bash、PowerShell、Python 3 isolated mode、Linux `/proc/self/fd`、Git、GNU Make、CC、WSL/Linux、SHA-256。

import signal

        raise SystemExit(f"held Git failed with {process.returncode}: {argv!r}")

import os
import stat

root = os.environ["RUN_ROOT"]

def identities(tree):
    result = set()
    for current, directories, files in os.walk(tree, followlinks=False):
        directories.sort()
        files.sort()
        for name in files:
            path = os.path.join(current, name)
            value = os.lstat(path)
            if stat.S_ISREG(value.st_mode):

## 任务 4：实现 fresh checkout、independent rebuild 和 hash equality

Metadata 只用于审计和 expected recipe 对账；metadata executable path、command 或 environment 不得直接执行。

实现设计规格 §8.1 冻结的 `git-local-no-hardlinks-procfd/v1` primitive：通过 held Git FD 执行 `git clone --local --no-hardlinks --no-checkout /proc/self/fd/{source_fd} {checkout_b}`，再 detached checkout exact commit。复用任务 1 已通过的真实命令，不允许另选 primitive。Clone 前后复核 source A identity；checkout B 验证 HEAD、tag peeling、Git layout、risky config、clean status、build 前 artifact-empty、无 alternates、与 source A 无共享 regular-file identity，并使用独立私有空 HOME。

- [ ] **步骤 3：独立执行固定 build recipe**

Verifier 独立解析 Python/Git/CC/Make，不能复用 metadata 选择的工具。使用与 primary 相同 recipe，在 checkout B 中通过 held Make FD构建。

- [ ] **步骤 4：在 runtime 前比较两个 binary**

- [ ] **步骤 5：执行 exact production held-FD recipe 的强制复现门禁**

使用刚实现的 production runner/controller，从受控路径解析并持有 Python、Git、CC 和 Make FD，以 versioned recipe 在两个独立 checkout 中重建。两次执行都必须使用 absolute deadline、stdout/stderr cap、独立 process group 和 TERM/KILL/wait 回收；逐项验证 tool identity、semantic argv/environment、空且不同的 HOME/TMPDIR、post-build artifact manifest 和 binary SHA-256 equality。任何 hang、output cap、process cleanup、tool identity、recipe、artifact manifest 或 hash 失败都将 task 标记 BLOCKED；在该门禁通过前不得继续 runtime、provenance、Rust API 或 PowerShell wrapper。

- [ ] **步骤 6：只运行 rebuild binary**

通过 held rebuild FD启动 Redis，使用 private runtime root、loopback dynamic port、`daemonize no`、关闭 persistence，并严格解析唯一 `redis_version:8.8.1`。

- [ ] **步骤 7：实现 cleanup-before-publish**

固定顺序：process group TERM/KILL/wait → 确认无本次验证存活进程 → runtime remove → checkout B 和 verification build log remove → temp root verify → 重新核验 primary metadata/binary/log、source A、tool FDs 和 output parent 的 identity/hash → 关闭每个不再需要且 close 可能失败的 evidence handle，仅保留已复核的 output publication handle → provenance atomic publish。任一 cleanup、handle close 或 identity/hash 复核失败，最终 output 必须不存在。

- [ ] **步骤 8：实现 normative provenance v2**
