# Redis 8.8.1 稳定性优先设计

> 状态：已批准文档方向；仅授权规划、接口冻结和兼容基础设施，不授权 Embedded Redis Hot Tier 生产实现
> 日期：2026-07-26
> Redis exact tag：`8.8.1`
> Redis exact commit：`77b6c308396c9700672390a210143a8496fb4b10`

关联决定：`D001`、`D002`、`D009`、`D010`、`D011`、`D012`。

主要需求：`REQ-COMPAT-001` 至 `REQ-COMPAT-010`、`REQ-STORAGE-001` 至 `REQ-STORAGE-006`、`REQ-STABILITY-001` 至 `REQ-STABILITY-006`、`REQ-HOT-001` 至 `REQ-HOT-012`、`REQ-RAFT-001` 至 `REQ-RAFT-008`、`REQ-LICENSE-001` 至 `REQ-LICENSE-008`、`REQ-WORK-001` 至 `REQ-WORK-005`。

## 1. 目的

Kiwi 的兼容合同、公开接口、测试 Oracle、未来原生热数据层接口和发行合规设计统一以 Redis 8.8.1 exact tag 为基线。

当前工程主线不是实现热数据层，而是先把没有热数据层参与时的系统做稳定：

```text
Redis 8.8.1 可观察语义合同
  → Cache OFF 命令与协议正确性
  → RocksDB 权威状态、格式和真实恢复
  → OpenRaft 单 Group 一致性和故障证明
  → 系统稳定性门禁
  → 用户重新批准
  → 才允许启动 Embedded Redis Hot Tier 实现
```

本设计将未来接口提前冻结，是为了避免兼容、持久化和 Raft 工作把热层假设写进核心路径；接口冻结不代表已获得实现、构建、链接、打包或发布 Redis 派生动态库的授权。

## 2. 固定身份

```text
Redis tag:              8.8.1
Redis commit:           77b6c308396c9700672390a210143a8496fb4b10
Compatibility Oracle:  exact Redis 8.8.1 binary/source
Kiwi language:          Rust
Authoritative storage:  RocksDB
Consensus:              OpenRaft
Current cache mode:     OFF
Future source fork:     github.com/arana-db/redis
Future library license: AGPL-3.0-only
```

所有机器可读 manifest、测试 transcript、构建 provenance 和发行 pairing 都必须记录 exact commit。浮动分支、`latest` 标签、系统包管理器当前版本和仅有版本字符串的二进制不能成为验收证据。

Required Oracle provenance 还必须通过 verifier-owned fresh checkout 独立重建，并证明 primary/rebuild binary SHA-256 完全一致。详细设计见 `docs/superpowers/specs/2026-07-28-redis-8.8.1-trusted-oracle-provenance-design.md`。

## 3. 当前系统完成定义

当前阶段只交付 Cache OFF 系统：

- Kiwi 不加载 Redis 派生 `.so`、`.dylib` 或 `.dll`。
- 生产 crate dependency graph 不包含 Redis 派生 native library。
- 客户端可见行为以 Redis 8.8.1 raw RESP differential 和最终状态对账判断。
- RocksDB 保存全量、权威、可恢复的数据和 TTL。
- OpenRaft 定义写入提交、状态机 Apply、线性一致读和成员变更边界。
- Redis 8.8.1 可作为独立测试 Oracle 运行，但不是 Kiwi 的运行时数据路径。
- redis-rs 只允许进入测试工具或 development dependency，不得进入生产服务器依赖图。

Cache OFF 不是临时降级路径，而是热层准入前必须独立达到生产稳定性的完整正确性基线。

## 5. 稳定性优先的阶段顺序

### S0：项目真相和恢复能力

完成 Redis 8.8.1 唯一基线、许可证选择、当前 Cache OFF 边界、工作恢复记录和任务授权边界。

退出条件：清空代理会话记忆后，仅凭 `.planning/`、本设计、当前计划和 `.codex/recovery/ACTIVE.md` 能继续工作，并能识别热层仍未获实现授权。

### S1：兼容 Oracle 和协议证据

建立 exact Redis 8.8.1 构建 provenance、raw RESP transcript、命令 manifest、known difference 和 skip 治理。

Oracle provenance 的退出条件包括独立 checkout、受控双构建、exact hash equality、运行 rebuild binary 和 cleanup-before-publish；单一构建方的 metadata 自述不满足 S1。

退出条件：代表性的 String、Hash、List、Set、ZSet、TTL、Pipeline 和连接错误场景可重复对照，差异不会被 typed client 或全局 normalization 隐藏。

### S2：RocksDB 权威状态

冻结磁盘格式、Key encoding、TTL 绝对时间、WriteBatch 原子性和恢复合同。恢复测试必须释放所有 RocksDB handle 后按路径重新打开。

退出条件：Cache OFF 下进程崩溃、部分写、损坏、磁盘满、Snapshot restore 和版本迁移均有可重复证据。

### S3：OpenRaft 单 Group

完成 Commit/Apply/durability 回复边界、线性一致读、成员变更、Leadership Transfer、Snapshot、持久日志 reopen 和确定性故障模拟。

退出条件：固定 seed 和进程级故障测试没有违反 Election Safety、Log Matching、State Machine Safety 和公开 RedisRaft 行为合同。

### S4：系统稳定性门禁

按 `docs/quality/system-stability-gate.md` 对兼容、存储、Raft、恢复、可观测性、资源上限和发行基础进行整体验收。

门禁通过是启动热层工作的必要条件，不是实现授权。

### S5：用户批准检查点

门禁通过后必须停止并向用户提供：

- exact Kiwi HEAD 和完整验证证据；
- 未关闭的 P0/P1、known difference 和风险；
- ABI 设计复核结果；
- `arana-db/redis` fork、许可证和 Corresponding Source 计划；
- 热层最小实现范围及回退方案。

只有用户在该检查点重新明确批准，才能建立热层实现任务、分支和代码变更范围。

## 6. 架构不变量

1. RocksDB 是唯一全量权威存储。
2. OpenRaft 一致性门禁不能被任何当前或未来的快速路径绕过。
3. Redis 8.8.1 定义客户端可见语义，不定义 Kiwi 的持久化实现。
4. Cache OFF 必须独立正确、可恢复、可运维并达到发布门禁。
5. 未来热层必须可完全删除并从 RocksDB 重建。
6. 热层状态不得进入 Raft Log、Snapshot、Backup 或稳定磁盘格式。
7. 热层更新失败必须 invalidate；已知旧值不得继续可见。
8. Snapshot Install、RocksDB reopen、格式迁移和配置世代改变必须使旧热层内容失效。
9. 所有公开协议、磁盘格式、FFI ABI 和 manifest 都必须版本化。
10. 第三方源码和二进制必须有 exact commit、许可证、修改清单、hash、SBOM 和可重现构建证据；Redis Oracle required evidence 必须通过 verifier 独立重建和 exact binary hash equality。

## 8. 变更控制

以下变化必须新建 Decision，不能作为普通实现细节处理：

- Redis exact tag 或 commit 改变。
- Redis fork、许可证选择或组合发行边界改变。
- RocksDB 不再保存全量权威状态。
- OpenRaft 一致性门禁或成功回复边界改变。
- Cache OFF 不再作为独立生产正确性基线。
- 热层由动态库改为静态链接、独立进程或其他隔离形式。
- ABI major version、allocator/ownership、线程或多实例合同改变。
- 在系统稳定性门禁通过前启动热层生产实现。
